description: 플레이어 눈에 보이는 것을 만들거나 고칠 때 사용 — UI 화면·HUD·캐릭터·장비·도구·아이콘·이펙트·동작(애니메이션)("인벤토리 화면 만들어", "도끼 모델 넣어줘", "걷는 동작 고쳐", "조잡해 보여"). 레퍼런스 시트 → 만들기 → 게임 카메라 캡처를 열어 대조 → 플레이어 눈 순서로 만든다.
---

1. `docs/conventions/Reference.md`, `docs/conventions/PlayerEye.md` 를 읽는다. 파일을 새로 들이면 `AssetNaming.md` 도 (엔진별 이름·폴더·들이는 법은 `docs/engines/<엔진>.md`).
2. **시트부터.** `docs/reference/` 에서 이 대상의 시트를 grep 으로 찾는다. 움직이는 것이면 동작 관찰표(`*_motion.md`)도.
   - 없거나, 있는데 "게임 카메라에서의 크기·자세"가 숫자가 아니면 `reference-sheet` 스킬로 먼저 만든다.
   - **루프 일꾼이면**: 정지 캡처로 되는 시트는 직접 만든다. 영상이 필요한 동작 관찰표가 없으면 INBOX `막힘`("동작 관찰표 필요: <대상>")으로 감독에게 넘기고 이번 바퀴는 다른 조각을 한다 — 추측으로 동작을 만들지 않는다.
3. 이미 있는 것을 먼저 찾는다 (같은 화면·메시·머티리얼, `tools/` 의 가공·들이기 스크립트). 있으면 새로 만들지 않고 고친다.
4. 시트 항목을 하나하나 그대로 만든다 (`Reference.md` §3). 생성 도구(이미지·3D·동작 — 이 프로젝트에서 쓸 수 있는 것은 `CLAUDE.md` "프로젝트" 절의 "만드는 도구")를 쓰면 여러 결과 중 시트와 가장 가까운 것을 고르고 생성 조건·라이선스를 남긴다 (`AssetNaming.md` "AI 생성 이미지"). 가공·들이기를 스크립트로 했으면 `tools/` 에 둔다 (`FolderStructure.md`).
5. 1·2층 검사 (`Verification.md`, `docs/checks/<엔진>.md`). UI 는 함수 호출이 아니라 실제 입력(클릭·터치·뒤로 가기)으로.
6. **게임 카메라로 찍고, 그 그림을 실제로 연다.** 에셋 미리 보기·에디터 뷰포트 캡처로 대신하지 않는다. 시트의 숫자(크기 비율·자세·동작 주기)를 그림과 게임에서 **재서** 범위 안인지 본다 (`Reference.md` §4). 밖이면 같은 작업 안에서 고치고 다시 찍는다.
7. `PlayerEye.md` 다섯 칸을 본다. 못 본 칸은 `못 함(이유 — 감독)`.
8. 기록한다: 연 그림 파일 이름 · 잰 값 · `3층 통과(레퍼런스 대조: docs/reference/<시트>.md)` · `플레이어 눈: ① … ⑤ …` 한 줄. 동작 관찰표가 있으면 "우리 지금" 칸을 ✅ + 잰 값으로 고친다.
9. 자리표시(네모·단색·기본 스킨)로 끝났으면 합격이 아니다 — STATUS 에 `〔임시 그래픽〕`, ROADMAP 에 `<대상> 레퍼런스 품질로` 조각을 추가한다.

이 파일과 규칙 문서 내용이 다르면 규칙 문서를 따른다.

---
name: inbox
description: 루프에게 지시·답·보정·철회·보류를 남기거나, 루프의 질문에 사람 답을 전할 때 사용("인박스에 적어줘", "루프한테 ~하라고 해", "그 질문 답은 ~야", "그거 취소"). 감독 전용 — 루프 일꾼은 InboxFormat.md 를 보고 직접 쓴다.
---

1. `docs/conventions/InboxFormat.md` 를 읽는다.
2. `docs/feedback/INBOX.md` 를 연다.
3. 사람 말을 종류 하나로 정한다: `지시`·`답`·`보정`·`철회`·`보류`·`승인` (감독이 발견한 문제는 `결함`·`막힘`, 모아 물을 건 `질문`). 방향·삭제·권리(🔴)가 빠져 있을 때만 되묻는다 (`Autonomy.md`). 숫자가 빠졌으면 묻지 않고 "숫자는 루프가 DESIGN §6 에 근거와 함께 정함" 이라 적어 저장한다.
4. 같은 주제의 이전 항목이 있으면 지우고 새 항목으로 대체한다 (뒤 것이 이긴다). `답` 은 해당 `질문` 바로 아래, 급하면 맨 위.
5. 작성자는 `감독←형` 처럼 누구 말인지 적는다.
6. 사람이 한 말을 그대로 옮기는 거라면 그대로 저장. 감독이 해석을 보탰으면 그 부분을 `〔해석: …〕` 로 표시해 **바로 저장**하고, 저장한 줄을 보여 준다. 되묻지 않는다 — 🟡 는 가정하고 진행이 원칙(`Autonomy.md`). 틀리면 사람이 `보정` 으로 고친다.
7. **저장 즉시 커밋**: `git add docs/feedback/INBOX.md` → `docs(inbox): <요지>`. 왜: 커밋 안 된 INBOX 는 루프가 못 건드린다.

이 파일과 규칙 문서 내용이 다르면 규칙 문서를 따른다.

# 결정 007: 탈것 탑승 조건 = 도감(Codex) 완성

> **대체됨(→ 결정 009)** 2026-09-24 — 도감 100% 는 목줄을 주고, 목줄을 탈것 종과 바꿔야 탄다(`009-mount-collar-exchange.md`).

- 날짜: 2026-09-22
- 정한 사람: 사용자 (Autonomy.md 🔴 2, 되돌리기 비싼 방향)
- 상태: 확정

## 상황
M6-06(탈것) 질문 중 "탑승 조건을 어떻게 얻나"가 방향 결정이라 감독 위임 범위 밖이었다(DESIGN 8.2 끝줄). 감독이 채팅으로 확인을 구했고, 사용자가 직접 답했다.

## 고른 것
**도감(Codex) 100% 완성제.** 존마다 도감이 있고 카테고리 3개(농사·사냥·낚시)로 나뉜다. 각 카테고리는 그 존에 있는 종을 전부 나열한 목록이고, 종 하나를 처음 획득(수확/처치·포획/낚시)하면 그 칸이 채워진다. 한 존의 도감 3칸이 전부 차면 그 존에서 탈것 탑승 가능. 레퍼런스 게임의 "탈것 길들이기" 자리를 대신하되, 퀘스트 개별 해금이 아니라 수집 완성제로 사용자가 방향을 정했다.

## 감독 판단 — MVP 범위 (숫자·구조, 위임 범위 안)
- **낚시(어류)가 게임에 없었다**(DESIGN 7절 MVP 제외) — 도감에 낚시 칸을 넣으려면 낚시 자체를 새로 만들어야 해서, 이미 있는 목장/작물 슬롯 패턴(거점 슬롯 → 시간 경과 → 수확, `URanchComponent`/`HarvestRanch`)을 그대로 재사용한다. 새 메커니즘(캐스팅 미니게임 등)을 만들지 않는다 — DESIGN 1절이 애초에 낚시를 "목장과 같은 내 거점 슬롯으로 합류"라고 못 박아 뒀다(DESIGN.md:20).
- **도감은 지금 존별이 아니라 전역(global) 하나로 MVP 를 잡는다.** 사용자 방향은 "존마다"지만, 지금 게임에 사냥존·거점존이 각 1개뿐이라(M6 오픈월드 확장이 아직 존을 늘리지 않았다) 존별 구조를 미리 만들면 안 쓰는 뼈대가 된다(YAGNI). 종 목록이 늘어난 존이 실제로 생기면(M6 확장 이후) 도감 데이터에 존 ID 열 하나만 추가하면 된다 — 지금 구조를 갈아엎지 않는 선에서 남겨 둔다.
- **도감 진행은 클라이언트가 직접 못 채운다** — 이미 있는 서버 권위 이벤트(포획 성공·목장 수확·낚시 수확)가 CloudScript 에서 성공 판정될 때 그 자리에서 Player Data `codex` 를 같이 갱신한다(DESIGN 4.8). 새 클라이언트 요청 엔드포인트를 만들지 않는다 — 재화 지급과 같은 판정 자리를 그대로 빌린다.

## 고려했지만 안 고른 것
- **퀘스트 개별 해금** (예: "돼지 10마리 잡기" 같은 태스크 목록) — 사용자가 명시적으로 "도감 채우는 조건"을 골라 기각.
- **존별 도감을 지금 바로 구조화** — 존이 2개뿐인 지금 시점엔 과설계. 존이 늘어나면 재확장.

## 결과 (좋아지는 것 / 감수하는 것)
- 좋아지는 것: 낚시가 기존 목장 패턴 재사용이라 새 시스템 리스크가 작다. 도감 진행이 서버 권위 이벤트에 얹혀서 클라이언트 조작 여지가 없다.
- 감수하는 것: 지금의 "전역 도감"은 존이 여러 개로 늘면 다시 손봐야 한다(존 ID 열 추가 수준으로 예상). 낚시가 미니게임이 아니라 목장과 똑같이 "기다리면 찬다"라 손맛은 약하다 — 필요해지면 별도 조각으로 액티브 낚시를 얹는다.

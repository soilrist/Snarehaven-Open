# 기능 명세: 목장 슬롯 (배치 · 수확)

- 상태: **검수 완료** (루프#29 작성 · 감독 검수 2026-09-19 — 3장 🟡 가정 승인, DESIGN 3.2 "슬롯 상호작용" 에 확정 기록)
- 마일스톤: M2 · 범위(커밋 scope): `ranch`
- DESIGN 연결: `DESIGN.md` 3.2(상태 머신·확정 수치) · 4.1(권위 2단) · 4.5(저장) · `BACKEND.md` `RegisterPet`·`HarvestRanch`
- ROADMAP 조각: M2-04 (아래 5장에서 M2-04a/b/c 로 쪼갬)

## 1. 합격 기준 (한 문장)
> "목장(`L_Ranch`)에 슬롯 5칸이 보이고, 빈 칸에 다가가 상호작용하면 포획한 펫 배치 **요청**이, 찬 칸에서는 수확 **요청**이 대기열에 쌓인다 — 칸의 표시는 백엔드가 보내 준 스냅샷을 적용했을 때만 바뀐다."

DESIGN 3.2 상태 머신(`Empty → Occupied → Ready → 수확 → Occupied`)에서 **상태를 굴리는 쪽은 백엔드**다. 이번 기능이 만드는 것은 그 상태를 받아 보여 주는 그릇과, 사람이 누른 것을 요청으로 바꾸는 길뿐이다 (CLAUDE.md 8).

## 2. 플레이어가 보는 것
- 입력: 사냥과 같은 **자동 상호작용 버튼**(`IA_Attack`) — 사거리 안 가장 가까운 슬롯 1개만 하이라이트 (M1-06 채집이 쓴 방식 그대로. 🟡 가정 — 3장 아래 주 참고)
- 화면: 슬롯 5개(올가미 모티프 자리표시). 빈 칸 / 펫이 있는 칸이 구분된다. Ready 알림 아이콘과 미수확 개수 표시는 **M2-06**
- 실패·예외:
  - 빈 칸인데 배치할 펫이 인벤토리 캐시에 없다 → 요청을 쌓지 않는다 (보유는 백엔드 스냅샷 기준 — DESIGN 4.5)
  - 이미 요청이 대기 중인 칸 → 같은 칸에 같은 종류 요청을 두 번 쌓지 않는다 (백엔드 왕복 전에 두 번 누르면 이중 지급으로 보인다)
  - 슬롯 번호가 0~4 밖 → 무시하고 경고만

## 3. 숫자 (전부 DESIGN 3.2 확정 수치 — 이번 기능에서 **새로 만드는 숫자 0개**)
| 이름 | 값 | 단위 | 출처 |
|---|---|---|---|
| 초기 목장 슬롯 수 | 5 | 칸 | DESIGN 3.2 확정 수치 |
| 생산 주기 | 30 | 분 | DESIGN 3.2 · `DT_RanchProductTable.CycleMinutes` |
| 미수확 누적 상한 | 5 | 개 | DESIGN 3.2 · `DT_RanchProductTable.MaxStack` |
| 사이클당 코인 | 10 | 스네어 코인 | DESIGN 3.2 — **클라이언트는 계산도 하지 않는다**, `HarvestRanch` 가 준다 |
| 상호작용 사거리 / 하이라이트 주기 | 150 / 0.6 | cm / 초 | DESIGN 3.1·3.3 — 공격·채집이 쓰는 값을 그대로 빌린다 (새 값 안 만든다) |

> 🟡 가정(루프#29): 입력을 `IA_Attack` 에 얹고 사거리·주기를 빌리는 것. 근거는 M1-06 채집에서 감독이 같은 이유로 확정한 선("모바일에 버튼을 종류마다 늘리지 않는다", DESIGN 3.3). 목장에는 동물도 채집물도 없어 대상이 겹치지 않는다. 다르게 가려면 INBOX `보정`.

## 5. 조각 나누기 (루프가 채움, 사람이 확인)
1. **M2-04a** `FRanchSlotState` + `URanchComponent` — 슬롯 5칸 캐시 + 요청 대기열. 함수는 두 갈래뿐: `ApplyBackendSnapshot()` 만 칸 내용을 바꾸고, `QueueRegisterPet(Slot, AnimalID)`·`QueueHarvest(Slot)` 는 `BACKEND.md` 표의 호출 인자를 그대로 담아 쌓기만 한다. **로컬 타이머·경과 계산·지급 계산 없음.** 검사는 2층 자동화 테스트. (C++ 만 — 에셋 0)
2. **M2-04b** `L_Ranch` 레벨 + `BP_RanchSlot` 자리표시 5개 배치 (커맨드릿 파이썬 — `engines/unreal.md`). 검사는 3층 캡처.
3. **M2-04c** 슬롯 상호작용 — 근처 슬롯 하이라이트 → 배치/수확 **요청**까지. 스냅샷이 오면 칸 표시가 바뀌는 것을 테스트에서 가짜 스냅샷으로 확인. 검사는 2층 + 3층 캡처.

> M2-04a 는 M2-01(PlayFab 플러그인, 보류) 없이도 끝까지 만들 수 있다 — 요청을 **보내는** 코드가 이번 범위 밖이기 때문이다. 감독 지시(2026-09-19 10:12)의 "요청 대기열 + 스냅샷 적용 경로만" 이 그 뜻이다.

## 6. 검사 방법
- 1층(기계): `python3 tools/check_conventions.py --engine unreal` → `오류 0 / 경고 0 / 미정 숫자 0` · 컴파일 통과
- 2층(동작):
  - 빈 슬롯에 `QueueRegisterPet` → 칸은 여전히 Empty 이고 대기열만 1건 (보유·배치가 요청만으로 바뀌지 않는다 — CLAUDE.md 8)
  - 같은 칸에 같은 요청 두 번 → 대기열 1건
  - 가짜 백엔드 스냅샷(`AnimalID=animal.pig`) 적용 → 칸이 Occupied 로 바뀌고, `DT_RanchProductTable` 에서 그 동물의 주기·생산 아이템을 찾을 수 있다
  - 칸 수가 5 가 아닌 스냅샷 → **하나도 반영 안 함** (인벤토리 `ApplyBackendSnapshot` 과 같은 전부-아니면-전무)
- 3층(눈): `L_Ranch` 를 헤드리스로 띄운 캡처에 슬롯 5개가 보인다 (`docs/checks/unreal.md` 의 `-SnareCapture=` 방법)

## 7. 하지 않을 것
- **백엔드 왕복** — 로그인·CloudScript 호출은 M2-01·M2-03 (사람 몫, 보류 중)
- **Ready 알림 아이콘·미수확 개수 UI** — M2-06
- **클라이언트에서 경과 시간으로 생산량 계산** — 영원히 안 한다. 화면에 남은 시간을 보여 줄 때도 백엔드가 준 `OccupiedSinceUtc` 를 표시만 한다 (DESIGN 4.1)
- 슬롯 확장 구매, 남의 목장 구경, 목장 복제(멀티) — DESIGN 3.2 가 확장 단계로 미뤘다
- 펫 고르기 화면을 만들지 않는다 — 빈 슬롯엔 인벤토리 캐시의 **첫 번째** 펫(`DT_AnimalTable` 순서)이 들어간다. 펫 고르기 UI 는 M2-06(목장 HUD) 항목 — 감독 확정(2026-09-19, 루프#31 확인 답)

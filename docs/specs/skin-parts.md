## 1. 합격 기준 (한 문장)
> "옷장 화면에서 칸 버튼(모자·얼굴 장식·상의·하의·신발·장갑·배낭)을 누르면 오른쪽 격자가 그 칸 꾸미기만 보이고, 하나를 누르면 캐릭터가 바로 그것을 입은 채(앞·뒤 돌려 보기) 보이며, 칸마다 일반·희귀·에픽 여러 벌이 옷장 젬 상점·꾸미기 상자에 걸려 있다 — 입은 것은 서버가 가진 것인지 확인한 뒤에만 남는다."

## 5. 데이터·에셋 짜임 (🟡 가정 — INBOX 확인)

1. **꾸미기는 장비 칸과 따로 사는 「겉모습 덮개」 다.** 새 `EItemType::Cosmetic`(10.9 `PetCosmetic` 과 같은 꼴, 능력치 0). 효과 모자·하이킹 배낭·구명조끼는 지금처럼 장비 칸에서 효과를 내고, 같은 칸에 꾸미기를 입으면 **보이는 것만 꾸미기**로 덮는다. 왜: 원본도 효과 모자와 꾸미기 모자가 따로 돌고, 꾸미기를 사면 효과를 잃는 구조면 아무도 안 산다. 10.3(돈이 능력에 닿지 않는다)도 그대로 지킨다.
2. **칸 열거형은 끝에만 붙인다** — `EEquipSlot` 에 `FaceAccessory`·`Shoes`·`Gloves` 를 뒤에 더한다(표에 저장된 순번이 밀리지 않게, `EBuffKind` 주석과 같은 규칙). `EQUIPMENT.md` 표 D 「열거형은 늘리지 않는다」 줄은 이 지시로 바뀐다.
3. **붙이는 길**: 얼굴 장식 = 스태틱, 머리 소켓 하나 더(`Socket_Face`, 머리 앞면) · 신발·장갑 = 옷과 같은 스켈레탈 레이어(뼈 따라감, 소켓 없음). 새 소켓은 `tools/unreal/setup_equipment_socket.py` 의 `SOCKETS` 한 줄.
4. **입은 꾸미기는 서버가 기억한다** — CloudScript `SetOutfit {slot, itemId}`(빈 `itemId` = 벗기) 가 인벤토리에 그 아이템이 있는지 보고 플레이어 데이터 `Outfit` 에 적는다(10.9 `SetPetCosmetic` 과 같은 길). 클라는 응답 뒤에만 입힌다 — 꾸미기는 젬 물건이라 「안 산 것을 입어 보이기」 를 막아야 한다(규칙 8). 남의 화면은 M9-06 처럼 칸별 아이템 ID 만 복제.
5. **옷장 화면** = 원본 흐름 그대로: 크림 둥근 칸 버튼 7 + 회전 버튼 둘레 · 오른쪽 크림 판 `내 꾸미기`/`전체` 탭 + 8열 원판 격자 + 아래 `상점 열기`(지금 `UWardrobeShopWidget` 으로) + `나가기`. 미리보기는 입은 그대로(누름 = `SetOutfit` 요청, 응답 뒤 갈아입음). 여는 곳은 지금처럼 배낭 「장비」 탭(옷장 가구는 다음 묶음).
6. **메시는 바르코 생성 + Blender 손질**(DESIGN 3.5 · 기존 모자 `hats_v2_make.py` 절차). 원본 그림·이름을 그대로 쓰지 않는다(Reference §5) — 「곰 모자」 처럼 종류는 따르되 생김새·이름은 새로.

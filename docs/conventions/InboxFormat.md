# INBOX 형식

## 한 줄 요약
**INBOX 는 사람·감독 ↔ 루프 우편함.** 맨 위가 제일 급함. 끝나면 **바로 지운다** (기록은 STATUS 에만).

## 한 줄 형식
```
- [ ] <종류>(작성자, YYYY-MM-DD HH:MM) **요지 한 줄.** 본문… 검증: <어떻게 확인> / 삭제: <언제 지움>
```
예:
```
- [ ] 지시(감독←형, 2026-09-15 21:10) **고블린 이동속도 3.5로.** SO_Enemy_Goblin 의 m_MoveSpeed = 3.5 검증: 검사기 미정 숫자 목록에서 사라짐 / 삭제: 커밋 후
- [ ] 질문(루프#128, 2026-09-15 21:40) **보스전 카메라 고정/추적?** ① 고정(추천: 레퍼런스가 고정) ② 추적. DESIGN 4.1 에 없음. / 삭제: 답 받으면
- [ ] 확인(루프#129, 2026-09-15 21:52) **적 시야 = 화면 절반으로 가정.** DESIGN 4.2 "보면 쫓아온다" 해석. 다르면 보정 부탁. / 삭제: 사람이 보거나 M1 합칠 때
- [ ] 결함(감독, 2026-09-15 22:05) **#130 STATUS 에 3층 통과라 썼는데 캡처 없음.** 캡처 찍고 기록 고칠 것. / 삭제: 고친 커밋 후
- [ ] 막힘(루프#131, 2026-09-15 22:30) **씬 병합 충돌 — 혼자 못 품.** Scenes/Game.unity. 이 범위는 건너뜀. / 삭제: 사람이 풀면
```

## 종류 (이것만)
| 종류 | 쓰는 쪽 | 처리하는 쪽 | 뜻 |
|---|---|---|---|
| `지시` | 감독(사람 말을 옮김) | **루프** | 해라 |
| `답` | 감독(사람 말을 옮김) | **루프** | `질문` 에 대한 답 — 질문 줄 바로 아래에. 루프가 반영 후 둘 다 삭제 |
| `보정` | 감독(사람 말을 옮김) | **루프** | 앞선 지시·가정을 조금 바꿈 |
| `철회` | 감독(사람 말을 옮김) | **루프** | 앞선 지시 취소 (루프가 해당 지시와 함께 삭제) |
| `결함` | 감독·루프 | **루프** | 루프가 고칠 수 있는 잘못 (버그, 거짓 검사 기록, 규칙 위반) |
| `질문` | 루프·감독 | 사람 (감독이 모아 물음) | 🔴 사람이 정할 것 (방향·돈·삭제·권리·규칙·사람만 할 수 있는 일). 선택지+추천. **밸런스 숫자는 질문이 아니다** — 루프가 DESIGN §6 에 근거와 함께 정한다 |
| `확인` | 루프·감독 | **감독** (검산해서 닫음) | 🟡 "이렇게 가정하고 진행 중" — **답 없어도 루프는 계속 간다.** 감독이 검수 때 맞으면 지우고(DESIGN `〔가정〕` 확정), 틀리면 `보정`, 방향이 걸렸으면 `질문` 으로 올린다. 사람에게 그대로 넘기지 않는다 |
| `막힘` | 루프·감독 | 사람·감독 | 루프가 혼자 못 푸는 문제. 루프는 **그 범위만 건너뛴다** |
| `보류` | 감독(사람 말을 옮김) | 사람 | 이 범위 건드리지 마 (사람이 작업 중) |
| `승인` | 감독(사람 말을 옮김) | **감독** | 규칙 변경·main 합치기 같은 감독 제안 허락. 루프는 건너뜀 |

## 규칙
1. **맨 위가 최우선.** 루프는 위에서부터 **처리하는 쪽이 루프**인 것(`결함`·`지시`·`답`·`보정`·`철회`)을 하나 집는다. 나머지는 건너뛴다. 판단 기준(🟢🟡🔴)은 `Autonomy.md`.
2. **끝난 항목은 즉시 삭제.** `[x]` 로 남기지 않는다. 왜: 쌓이면 다음 바퀴가 끝난 걸 또 읽고 토큰을 먹는다.
3. **같은 주제는 뒤에 쓴 게 이긴다.** 앞 것은 지운다.
4. **답 하나 = 커밋 하나.**
5. **INBOX 를 고친 쪽이 바로 커밋한다.** 감독은 `docs(inbox): <요지>`, 루프는 그 바퀴 커밋에 포함. 왜: 커밋 안 된 INBOX 는 다음 바퀴가 "남의 변경"으로 보고 못 건드린다.
6. 루프가 항목을 지울 때 STATUS 에 `INBOX 처리: <요지>` 한 줄.
7. `logs/alerts.log`(loop.sh 경고)는 INBOX 가 아니다. 감독이 읽고 필요하면 INBOX 로 옮긴다.
8. **루프는 자기 몫 줄만 읽는다** (`결함`·`지시`·`답`·`보정`·`철회`·`보류`·`막힘` — PROMPT ②). `확인`·`질문`·`승인` 은 감독·사람 몫이라 루프가 읽지 않는다. 왜: 안 닫힌 확인이 쌓이면 INBOX 를 통째로 읽는 값이 매 바퀴 든다.
9. **상시 규칙을 INBOX 에 두지 않는다.** "삭제: 하지 않음" 인 줄은 우편함이 아니라 규칙이다 → 컨벤션 문서나 `CLAUDE.md` 로 옮기고 지운다 (DIRECTOR.md "문서 살림" 4).
10. **INBOX 는 12,000자, `확인`·`질문`·`승인` 은 합쳐 10개를 넘기지 않는다.** 넘으면 `loop/ctl.sh size` 와 `alerts.log` 가 알린다 — 감독이 닫는다.
11. 사람이 직접 한 지적은 **사람 말을 따옴표로 그대로** 옮기고, `PlayerEye.md` 의 어느 칸인지 `〔플레이어 눈 ③〕` 처럼 단다.
12. **`확인`·`막힘` 은 STATUS 를 복붙하지 않는다 — 2문장 이내, 판단 개수와 근거 `파일:줄`(또는 STATUS 바퀴 번호) 하나.** 예: `확인(루프#126, …) **버튼 이름·자리 🟡 셋.** 근거는 STATUS #126. / 삭제: 감독이 보면`. 왜: 전체 서술은 이미 STATUS 에 있다. 또 옮기면 읽는 쪽 토큰만 먹는다 (Snarehaven 실측).

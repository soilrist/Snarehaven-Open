# 레퍼런스 규칙 — 놀이는 따르고, 겉모습은 우리 것으로

## 한 줄 요약
**레퍼런스 게임을 하나 정하면, 그 게임의 시스템·콘텐츠 구성·조작 흐름·품질 수준은 따라 만들고, 화면 배치·모양·색·캐릭터 얼굴·글은 우리 것으로 다르게 만든다 (6절 — 2026-10-11 사용자 지시 「너무 비슷으면 권리 문제」).**
"비슷한 느낌의 다른 게임"을 만들지 않는다. 왜: 느낌만 따라가면 매번 조잡하고 허접한 결과가 나왔다. 기준이 구체적일수록 결과가 좋다.

비유: 요리 학교에선 먼저 레시피를 그대로 따라 만든다. 변주는 그대로 만들 수 있게 된 다음이다.

## 1. 레퍼런스 정하기 (kickoff · 🔴 방향)
- DESIGN §1 에 **주 레퍼런스 하나** + 보조 0~2개(어느 부분만). 사람이 정하고, 바꾸는 것도 🔴.
- 정해지면 웹에서 조사해 DESIGN 을 채운다: 시스템(§4), **콘텐츠 목록(§5)**, 화면 목록(§8), 아트 규격(§7), 밸런스 감각(§6 근거).
- **§5 콘텐츠 목록의 기본값은 "레퍼런스에 있는 것 전부"다.** 캐릭터/직업 · 무기·방어구 · 몬스터 · 퀘스트·퀘스트 카드 · 가챠/뽑기 · 상점·재화 · 성장·강화 · 이벤트 — 레퍼런스에 있으면 목록에 있어야 한다. 빼는 건 §10 "범위 밖"에 이유와 함께. 왜: "리니지 같은 게임"에 캐릭터·무기·퀘스트·가챠가 없으면 리니지 같은 게임이 아니다.
- ROADMAP 은 §5 의 항목이 전부 조각으로 깔릴 때까지 계획 바퀴를 돈다. "핵심 루프만 있고 콘텐츠는 나중에"로 끝내지 않는다.

## 2. 레퍼런스 시트 — 만들기 전에 (🟢)
UI 화면·캐릭터·무기·아이콘·이펙트처럼 **보이는 것을 만드는 조각은 시트부터.** `docs/reference/<대상>.md` 한 장:
```
# 레퍼런스 시트: 인벤토리 화면
- 원본: 〔게임〕 〔화면/대상 이름〕 — 캡처 파일 `_Source/reference/inventory_01.png` (깃 제외)
- 구성: 격자 5×8, 왼쪽 캐릭터 슬롯 6칸, 상단 탭 3개(장비/소모품/기타), 하단 정렬·버리기 버튼
- 색·서체·크기: 배경 #1a1610, 슬롯 64px, 서체 굵은 고딕 14px, 등급색 5단계
- 조작 흐름: 탭 → 슬롯 탭 → 툴팁 → 장착/사용
- 게임 카메라에서의 크기·자세 (숫자로): 〔캐릭터·장비·동작이면 필수. 예: 손도끼 길이 = 캐릭터 키의 35~45% · 기본 카메라에서 얼굴이 보임 · 서 있을 때 팔을 내린 자세(싸움 자세 아님) · 던지기 동작 0.5초 이내〕
- 우리 것과 다르게 할 점 (있으면, 이유):
```
- **크기·자세는 말이 아니라 숫자로 적는다.** "레퍼런스처럼"은 대조할 수 없다. 레퍼런스 캡처에서 캐릭터 키 대비 비율·화면 높이 대비 비율·동작 시간을 재서 범위로 적는다. 왜: "원본 자세랑 맞추라"는 같은 지적이 여러 번 반복됐는데, 시트에 숫자가 없어서 매번 "맞췄다"고 통과했다.
- 캡처 원본은 `_Source/reference/` (깃 제외 — 남의 저작물). 깃에는 글로 풀어 쓴 시트만.
- 시트 없이 만든 UI·캐릭터는 검사 3층 "못 함(시트 없음)" 이다.

## 2-1. 움직이는 것은 영상으로 — 동작 관찰표 (🟢)
걷기·도구 쓰기·공격·낚시·화면 전환처럼 **움직이는 것은 정지 캡처로는 알 수 없다.** 레퍼런스의 플레이 영상(유튜브 등)에서 그 장면을 **프레임으로 잘라 눈으로 보고** `docs/reference/<대상>_motion.md` 관찰표를 만든다:
```
| 동작 | 출처 (영상 ID + 시각) | 원본에서 본 것 | 우리 지금 (틀린 점 → 고친 뒤 ✅ 잰 값) |
|---|---|---|---|
| 걷기 | `〔영상ID〕` 0:06~0:08 | 두 발 한 주기 ≈ 0.67초 · 걸음마다 몸이 위아래로 튐 · 팔은 작게 흔듦 | 주기 1.1초, 팔을 크게 흔듦 |
| 톱 들고 있기 | `〔영상ID〕` 8:09~8:13 | 날이 위로, 두 손으로 가슴 앞 | 한 손으로 내려 듦 |
```
- **누가**: 프레임 시트는 **감독**이 만든다. 일꾼은 표를 읽고 만든다. 왜: 영상을 받고 자르는 스킬·도구는 보통 사람 전역 설정에 있는데, 가벼운 바퀴(`LOOP_LEAN=1`)의 일꾼은 프로젝트 `.claude/skills/` 만 본다. 일꾼에게도 시키려면 그 스킬을 프로젝트 `.claude/skills/` 에 넣는다.
- **어떻게**: 영상 보는 스킬(예: 전역 `watch`)이 깔려 있으면 그걸 쓴다. 없으면 `yt-dlp` 로 그 구간만 받아 `ffmpeg` 로 프레임을 한 장에 타일로 붙여(예: 12fps) 그림으로 연다. **자막·설명 글만 읽고 "영상을 봤다"고 하지 않는다** — 동작은 프레임을 봐야 안다.
- **출처는 영상 ID + 시각.** 다음에 같은 장면을 바로 다시 찾을 수 있게.
- **숫자와 사실로**: 한 주기 몇 초 · 예비 동작이 있나 · 한 번 누르면 한 번인가, 누르는 동안 반복인가 · 한 손인가 두 손인가 · 도구가 어디를 향하나.
- **못 본 것은 `확인 못 함`** (가려서 안 보임·캐릭터가 몇 픽셀)이라고 적는다. 추측으로 칸을 채우지 않는다. 사람이 원본을 알고 말해 준 것은 `(사람 YYYY-MM-DD 직접)` 으로 적고 관찰보다 우선한다.
- **한 번에 다 본다.** 손에 드는 것·동작이 여러 개면 전 품목을 한 표에. 왜: 품목마다 따로 보면 같은 영상을 다시 받고 다시 본다 — 두 번 일한다.
- **프레임·영상 파일은 깃에 넣지 않는다** (남의 저작물 — §5). 깃에는 표만.

## 3. 만들 때
- 시트의 **기능 항목**(탭 수·조작 단계 수·정보 종류)은 빠짐없이 구현한다. 배치·모양·색은 6절대로 우리 것으로. "대충 비슷하게" 금지 — 품질은 레퍼런스 급, 겉모습은 다르게.
- 캐릭터·무기·아이콘: DESIGN §7 규격 + 시트의 실루엣·비율·색 배치. 생성 이미지는 **여러 시드 중 시트와 가장 가까운 것**을 고르고 프로그램으로 마감(배경 제거·크기 맞춤·팔레트)까지 한다 (AssetNaming.md "AI 생성 이미지").
- **자리표시 품질로 `[x]` 를 찍지 않는다.** 네모·단색·기본 폰트·기본 버튼 스킨은 조각 합격이 아니다. 임시로 넣었으면 STATUS 에 `〔임시 그래픽〕`, ROADMAP 에 `<대상> 레퍼런스 품질로` 조각을 바로 추가.

## 4. 검사 (3층에 추가)
**실제 플레이 시점(게임 카메라)** 캡처와 레퍼런스 캡처를 **나란히** 놓고 본다. 에셋 미리 보기·에디터 뷰포트 캡처로 대조하지 않는다 — 플레이어가 보는 화면이 아니다:
- [ ] 시트의 크기·자세 숫자가 게임 카메라 캡처에서 범위 안이다 (잰 값을 STATUS 에 적는다)
- [ ] 움직이는 대상이면 동작 관찰표(2-1)의 주기·자세를 **게임에서 잰 값**과 대조했다 (잰 값을 표의 "우리 지금" 칸과 STATUS 에 적는다)
- [ ] 구성 요소의 개수가 시트와 같다 (위치·모양은 6절 「다른 점 3」)
- [ ] 정보 밀도(글자 크기·여백)가 레퍼런스에 가깝다
- [ ] 캐릭터·아이템의 비율·실루엣이 레퍼런스 급이다 (기본 도형·플레이스홀더 아님)
- [ ] 서체·색이 DESIGN §7 팔레트다
- [ ] 조작 흐름(탭 수·단계 수)이 시트와 같다

하나라도 아니면 3층 **실패** → 같은 바퀴 fix, 못 고치면 INBOX `막힘` + ROADMAP 조각 추가. STATUS 검사 칸에 `3층 통과(레퍼런스 대조: docs/reference/<대상>.md)` 처럼 **어느 시트와 대조했는지** 적는다.

## 5. 권리 (🔴 — Autonomy.md)
- 레퍼런스의 **그림·소리·이름·대사·로고를 그대로 쓰지 않는다.** 구성·규칙·흐름·숫자 감각을 따르는 것과 원본 파일을 쓰는 것은 다르다.
- 캐릭터·지명·아이템·스킬 이름은 새로 짓는다. 레퍼런스 고유명사가 에셋 이름·데이터 ID·화면 글자에 들어가면 위반이다.

## 6. 다르게 — 우리 겉모습 (2026-10-11 사용자 지시)
게임 규칙·아이디어는 법이 보호하지 않지만, **겉모습(배치·그림·캐릭터·글)과 전체 인상**은 보호한다. 그래서 나눈다:
| 따른다 (아이디어) | 다르게 한다 (표현) |
|---|---|
| 시스템·놀이 순환·숫자 감각 · 조작 단계 수 · 장르 상식 UI(가방 격자·체력 막대·조이스틱) | 화면 배치·구도 · 판·단추 모양과 테두리 · 색 팔레트 · 아이콘 그림 · 캐릭터 머리·얼굴·실루엣 · 건물·지형 꼴 · 글·대사·이름·로고 · 소리 |
- **우리 겉모습 주제 = 「목장 나무판과 밧줄」** (DESIGN §7): 판은 나무결 판 + 밧줄 테두리, 머리띠는 진한 나무색 표찰. 레퍼런스의 크림색 둥근 판을 그대로 쓰지 않는다.
- 보이는 조각마다 STATUS 에 **「다른 점 3」** 을 적는다: 레퍼런스와 나란히 놓고 배치·모양·색 중 적어도 3가지가 다르다는 것. 나란히 놓았을 때 **같은 게임 화면으로 읽히면 3층 실패**.
- 레퍼런스 시트의 숫자(크기·비율·위치)는 **목표가 아니라 범위 참고**다. 「원본처럼 화면 폭 29%」 같은 지시는 쓰지 않는다.
- 스토어 스크린샷·아이콘·타이틀 화면·캐릭터 얼굴은 특히 엄격히 — 첫인상이 닮으면 안 된다.
